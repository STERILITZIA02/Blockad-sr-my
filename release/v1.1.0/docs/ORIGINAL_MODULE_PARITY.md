# 11 个原模块功能与替代对照

- 审计日期：2026-07-26
- 稳定版本：v1.1.0
- 适用目标：Shadowrocket
- 结论性质：源码、接口、上游、构建与 fixture 验证；未进行 iPhone/Shadowrocket 真机测试

本表回答三个问题：原文件原本试图避免什么广告或提供什么功能、本项目实际替代了
什么、出于什么原因没有替代什么。原文件完整保留在 `现有插件/` 供回溯，但不进入
稳定模块的运行依赖。

## 逐文件对照

### 1. `4in1.module`

- 原功能：把 Google 中“模块、插件、重写、sg、覆写”等特定搜索词 302 跳转到
  yfamilys 的五个索引页。
- 原本避免的广告：无；这是书签/快捷入口功能。
- 已替代：无。用户提供的 `yfamilys.com/shadowrocket` 仅作为审计参考来源记录。
- 未替代：全部 5 条搜索跳转。它会改变用户主动搜索并把搜索意图发送到第三方，
  不应随去广告订阅默认启用。

### 2. `AdBlock.module`

- 原功能：264 条 Rewrite，按 161 个旧软件分组处理开屏、横幅、活动弹窗、首页与
  信息流推广、广告素材、曝光/点击日志和少量启动配置。
- 主要目标：淘宝/闲鱼/飞猪/淘票票、高德、优酷、AcFun、百度系、京东、微博、
  知乎、网易、视频/音乐/阅读/出行/购物/工具等长尾 App。
- 已替代：157/161 个原软件组已迁移到独立组件、当前接口替代或安全的部分迁移；
  旧的无类型 `reject` 被改成明确的 `reject-dict`、`reject-array`、`reject-200`
  或本地字段过滤。共享图片尺寸、日志总入口、静态 IP 和大范围 CDN 匹配被删除。
- 未替代：
  - Bilibili：用户已有专用规则，本仓库发行物不包含相关组件或执行入口。
  - 饿了么：旧方案依赖共享 CDN 图片尺寸、视频名和 sitemap 猜测，误伤商品媒体。
  - 国泰君安：旧方案清空金融 App 混合配置，缺少字段证据。
  - 腾讯视频：近期维护来源已停用相关规则，恢复会威胁正片和清晰度选择。

### 3. `adultraplus.module`

- 原功能：2,098 条 Rewrite、380 个脚本入口和 118 个不同远程脚本 URL；覆盖大量
  App 的开屏、预加载、信息流、搜索推广、弹窗、活动、更新提示、UI 精简、追踪、
  PCDN、推送相关接口及便利功能。
- 已替代：
  - 广告专用路径拆分为独立 App 组件；混合响应由有界、幂等、本地 JSON 处理器按
    强广告信号过滤。
  - 新补回京东首页营销规则、滴滴 `getRuled/getPreload/getPasMultiNotices`、
    车来了 `getSkipAdvert/getNoticeWithAdvByCity`、向日葵 iOS 推广/启动素材、
    乐橙 `advertisementPush` 和华住广告/弹窗入口。
  - 追踪和已验证 PCDN 进入独立组件；知乎链接直达、闲鱼 UI 精简进入默认关闭组件。
  - 所有正式脚本本地化或固定版本；不再执行原来的 410 个动态脚本入口。
- 未替代：
  - 会员、付费、下载、倍速、皮肤、地区、后台播放等账户/权益改写。
  - `ios/version`、`bundle/upgrade/check` 等 App 更新和必要配置拦截。
  - 通知、评论、聊天、订单、支付、账号、设备告警等混合或正常功能接口。
  - 未固定 `main/master`、gist、Worker、日志/配置上报脚本及来源不明远程代码。
  - APNs、友盟、极光、个推等共享推送通道；它们同时承载正常消息，不能安全地按
    传输域区分营销推送。

### 4. `bili-region.module`

- 原功能：Bilibili 港澳台番剧自动换区、搜索词联动以及豆瓣评分显示。
- 原本避免的广告：无。
- 已替代：无；用户已有专用 Bilibili 规则，本仓库发行物不包含相关 Rewrite、
  响应脚本、独立组件或 MITM 主机。
- 未替代：自动换区、豆瓣评分及全部 Bilibili 去广告功能。旧实现改写地区/播放
  选择并在运行时请求豆瓣，既不属于去广告，也可能影响播放和隐私；由用户现有
  专用规则完整接管。

### 5. `fanqie.module`

- 原功能：番茄小说的穿山甲广告拉取、配置、素材、预加载、追踪、遥测与 PCDN；
  同时含 31 条域名/IP 规则。
- 已替代：保留精确广告 SDK、广告素材/章末广告、广告预取和可验证 PCDN；开屏
  配置与素材在每次请求时持续生效。
- 未替代：非法 `DOMAIN,*...`、共享 `bytedance.com/byteimg` 整域、`zijieapi`
  关键词、漂移静态 IP、正常小说/听书/视频与即时通讯基础设施。第一方加密正文
  feed 中没有可验证字段的原生推广仍无法可靠删除。

### 6. `gddt.module`

- 原功能：高德开屏、首页、消息盒、DSP 画像、搜索热词、归因 GIF 和场景推荐；
  原文件还错误地拒绝天气接口。
- 已替代：修正 5 个把 `pattern=` 写成第二个 `script-path=` 的确定性错误；使用
  本地响应处理器过滤明确商业卡，并保留精确开屏/归因/推荐 Rewrite。
- 未替代：天气拒绝和全站 `*amap.com` 粗放处理。定位、导航、路线、订单、天气和
  正常消息均明确保留。

### 7. `wechatad.module`

- 原功能：清理微信公众号文章接口 `getappmsgad` 返回的文章广告。
- 已替代：本地幂等处理器清空 `advertisement_info` 等广告字段，保留文章正文和
  `appid`；解析失败返回原响应。另处理明确的公众号联盟商品广告接口和朋友圈
  广告专用素材域。
- 未替代：任何聊天、支付、小程序、视频号、账号或通知接口；也不执行旧的
  NobyDa `master` 远程脚本。

### 8. `weibolitead.module`

- 原功能：微博轻享版 SDK 广告、开屏、搜索建议/热搜推广、推荐/关注/趋势流广告。
- 已替代：修复 `^ttps?` 协议拼写；补入实时/预加载开屏和第一方广告预加载；
  本地按广告 ID、类型、商业字段和追踪组合信号过滤信息流，重复执行保持幂等。
- 未替代：会员图标、皮肤或账户 UI 伪装；不屏蔽通知激活、私信、评论、账号和
  支付。没有强广告标记的普通运营内容会保留。

### 9. `YouTubeAd.sgmodule`

- 原功能：YouTube/YouTube Music Protobuf 广告过滤、广告统计阻断、PiP、后台
  播放、下载、字幕/歌词和 UI 开关；还包含全 UDP/QUIC 拒绝。
- 已替代：固定并校验近期 Maasea Protobuf 脚本，只保留广告节点过滤、广告统计、
  本地 UI 精简和默认关闭的字幕/Shorts 选项；删除外部请求和无界学习缓存。
- 未替代：PiP、后台播放、下载等权益伪造，全 UDP/443 封锁，配置/日志路由和
  远程 Worker。上游 encrypted `initplayback` 方案会把完整目标 URL 和 client
  key 交给第三方 Worker，违反本项目隐私/外部依赖边界；因此服务端拼接、第一方
  加密实验流和客户端原生广告无法保证清除。

### 10. `ZhihuBlock.sgmodule`

- 原功能：知乎开屏、商业横幅、推荐/热榜/搜索、品牌问题、文章/回答推荐、通知、
  评论、账号页、配置和 UI 精简。
- 已替代：精确商业接口直接空响应；推荐/热榜/回答/文章中只删除强广告标记对象；
  链接直达作为独立默认关闭组件。
- 未替代：静态 IP、通知计数、系统消息、评论、完整问题/文章、账号、全量配置、
  搜索词和正常推荐整接口清空。这些入口会破坏用户依赖的正常功能。

### 11. `ZhihuOpt.sgmodule`

- 原功能：知乎链接去中转、`oia` 文章/回答直达，以及两组全站 User-Agent/页面
  布局伪装。
- 原本避免的广告：无；属于网页便利/UI 功能。
- 已替代：链接直达保留在 `extras/zhihu-link-direct.sgmodule`，默认关闭。
- 未替代：全站 User-Agent 和布局伪装，避免登录、验证码、页面兼容和风控异常。

## 第一方加密与推广推送的最终边界

- 已处理的第一方二进制：只保留 YouTube 固定 Protobuf 处理器。本轮曾核对
  Bilibili `ViewReply.cm` 方案，但按用户要求完全排除，以免与已有专用规则重复。
- 已处理的推广推送：仅限 URL 路径明确表达 advertisement、marketing、promotion、
  popup-with-ad 或启动推广的业务接口；混合通知响应只做字段级强信号过滤。
- 未处理的共享推送传输：APNs、友盟、极光、个推及类似共享服务，因为阻断它们会
  同时丢失聊天、订单、设备告警、安全提醒和其他正常通知。
- 无法解密的第一方 feed、证书固定、HTTP/3 直连和服务端拼接内容不会用共享域、
  CDN、IP 网段或正常业务接口的粗暴封锁来伪装成功。
