## 保留的特殊、客制化与便利功能

- 微信公众号文章页广告区持续过滤。
- YouTube 上传/选段按钮精简；Shorts 隐藏和字幕改写保持脚本内默认关闭。
- 知乎链接去中转作为独立、默认关闭模块。
- 闲鱼搜索、消息和个人页推荐精简作为独立、默认关闭模块。
- 高德首页/搜索中带明确商业信号的 UI 精简，同时保留天气。
- 独立 `privacy-pcdn` 组件保留精确 PCDN、追踪和遥测拦截。
- 历史聚合模块的长尾 App 已拆成独立精确组件；第三方广告 SDK/域名再由固定的
  AWAvenue 安全快照兜底。

未保留的“特殊功能”均有明确原因：会员/倍速/下载/付费/皮肤/区域权益修改违反安全
边界；第三方搜索跳转、豆瓣请求、动态 Worker 和日志路由增加隐私或供应链风险。

## 冲突与性能结论

- 同一 Script pattern 只有一个处理入口；构建时发现不同处理器竞争会直接失败。
- URL Rewrite 同 pattern 不允许存在不同动作；重复规则、MITM 主机在构建时去重。
- v1.1.2 统一模块由 165 个默认启用的 App/功能组件生成，合并后为 23 条规则、
  223 条 Rewrite、30 个本地脚本入口和 274 个去重精确 MITM 主机；166 个独立
  组件仍全部发行，其中富途因金融风险默认关闭。另有 40 条独立组件域规则已被
  内置 AWAvenue 安全快照覆盖，因此只在独立组件保留，
  不在统一模块重复执行。
- 统一响应路由器最多读取 4 MiB，遍历最多 4,096 个对象、深度最多 8；不递归扫描
  无关超大对象。
- 过滤器重复执行保持稳定；解析失败、结构未知或大小超限时原样返回。
- 正式响应脚本不发外部请求、不轮询、不使用无限缓存。
- MITM 不含 IP/CIDR、端口或通配主机；构建与发行检查会拒绝任何 `*.` MITM。

## v1.1.2 正常功能回归审查

- v1.1.1 的抖音组件错误扩大了 HTTPS 解密范围：`*.amemv.com` 和
  `*.snssdk.com` 同时承载 feed、刷新、评论、发布、搜索、直播与上传。这与用户
  报告的“无法下滑刷新、打不开评论”一致，因此 v1.1.2 完全撤下两项及共享
  `pstatp` 通配 MITM。
- 穿山甲/Gromore/GDT 整域拒绝改为精确广告载荷空响应；SDK 握手、配置依赖和
  日志连接从 AWAvenue 拦截中排除，避免断连重试阻塞 App。
- 对其余 11 个通配 MITM 逐项复核：有明确当前主机的收窄为精确主机；只有旧
  聚合规则、共享 CDN 或高风险业务域依据的素材兜底撤下。
- 微信、QQ、京东、淘宝、抖音、菜鸟核心 URL，以及 APNs 外的友盟/极光/个推、
  GDT、穿山甲和 Bugly 基础依赖均加入“不应命中”测试。

## 与原版相比的主要修改

- 把 11 个整包叠加改成一个生成式统一模块、166 个真实独立开关和 2 个默认关闭的
  便利组件；相同接口只保留一个处理入口。
- 将开屏从“只挡素材”扩展为配置、预加载、素材和每次响应持续过滤，并补齐腾讯
  新闻、京东、淘宝、微博和抖音的当前精确入口。
- 补回经收窄的京东、滴滴、车来了、向日葵、乐橙和华住营销/弹窗接口；正常通知
  和共享推送通道保留。按用户要求完全排除 Bilibili 规则、脚本和 MITM 主机。
- 发布前再次复核所有旧软件组，新增优酷、爱阅书香、悦Me TV、搜狗输入法、
  超级课程表、等等付和直播吧的安全路径，并纠正微信、追书神器的迁移映射。
- 把远程 `main/master` 脚本替换为本仓库本地处理器或固定、校验过的第三方快照；
  响应脚本不再发外部请求。
- 将字符串关键词/任意图片尺寸/静态 IP/共享 CDN 的粗放判断改成明确字段、多特征
  组合和有界遍历；解析失败或未知结构返回原响应。
- 将知乎链接直达和闲鱼非广告 UI 精简单独隔离；会员、皮肤、倍速、地区、后台
  播放、下载和支付/账户权益修改全部移除。

## 未直接迁移的原软件组

- 饿了么：截至固定上游检查点仍只按共享 `elemecdn` 图片尺寸、视频文件名和
  sitemap 路径猜测广告，无法证明素材专属性。
- 国泰君安证券：近期聚合规则仍直接清空 `kvController`；这是金融 App 的混合配置
  入口，缺少响应结构证据，不以账户/交易风险换覆盖数。
- 腾讯视频：近期维护聚合包已经把视频 CDN、`vmind` 和 `getvinfo` 规则全部注释；
  恢复它们可能破坏正片、播放回退或清晰度选择。

## 无法可靠处理

- YouTube 服务端拼接、尚未覆盖的第一方加密、客户端原生或实验分流广告；当前
  上游 encrypted `initplayback` 需要把完整目标 URL 和 client key 重定向到第三方
  Worker，本项目不以隐私和播放链路为代价采用。
- 抖音等第一方加密 feed 中未暴露可验证广告字段的原生推广。
- Bilibili 全部由用户已有专用规则处理；本仓库发行物不包含其 Rewrite、脚本、
  组件或 MITM 主机，避免重复 MITM 与多脚本竞争。
- 通过 APNs、友盟、极光、个推等共享通道发送且没有独立营销业务接口的推广通知；
  传输层无法与聊天、订单、设备告警或安全提醒可靠区分。
- TLS 证书固定、HTTP/3 客户端直连或不经过 Shadowrocket 解密的流量。
- 已写入 App 本地数据库/磁盘的旧广告。
- 无明确广告字段的第一方运营卡片；为避免误删正常内容，默认保留。

这些边界不会用破坏视频、登录、支付、消息、评论、上传、下载或更新的宽泛封禁来
伪装成功。实际 App 版本仍需按 `docs/INSTALL.md` 完成真机验收。
